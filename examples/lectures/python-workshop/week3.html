Python workshop, week 3: files, errors, a small program

Reading a text file

In these notes, the block right after a piece of code shows what that code prints, or the last line of the error it raises.

First a file to read. open with mode "w" creates the file (or empties an existing one), and with closes it when the block ends, even after an error. Always name the encoding: the default differs between systems.

lines = ["walker,trail,km", "ana,Loop,12", "ben,Falls,7", "ana,Ridge,5"]
with open("trips.csv", "w", encoding="utf-8") as f:
    f.write("\n".join(lines) + "\n")

A file opened for reading is a sequence of lines. Each line still ends with its line break:

with open("trips.csv", encoding="utf-8") as f:
    for line in f:
        print(repr(line))
'walker,trail,km\n'
'ana,Loop,12\n'
'ben,Falls,7\n'
'ana,Ridge,5\n'

strip() removes it:

with open("trips.csv", encoding="utf-8") as f:
    rows = [line.strip() for line in f]
print(rows)
['walker,trail,km', 'ana,Loop,12', 'ben,Falls,7', 'ana,Ridge,5']

Parsing lines into records

A line is one string. split(",") cuts it into fields, which are strings too, so a number must be converted. The first row here is a header and is skipped with a slice.

trips = []
for row in rows[1:]:
    walker, trail, km = row.split(",")
    trips.append((walker, trail, int(km)))
print(trips)
[('ana', 'Loop', 12), ('ben', 'Falls', 7), ('ana', 'Ridge', 5)]

Real files have blank lines, often one at the end. A blank line splits into one empty field, and unpacking it into three names fails, so skip it first:

text = "ana,Loop,12\n\nben,Falls,7\n"
for line in text.splitlines():
    if not line.strip():
        continue
    print(line.split(","))
['ana', 'Loop', '12']
['ben', 'Falls', '7']

Handling errors

An operation that cannot finish raises an exception, and the program stops unless the exception is handled. try runs a block; except names the kind of error to handle and what to do instead.

def to_km(text):
    try:
        return int(text)
    except ValueError:
        return None

print(to_km("12"), to_km("twelve"), to_km(""))
12 None None

A missing file raises FileNotFoundError:

try:
    with open("missing.csv", encoding="utf-8") as f:
        data = f.read()
except FileNotFoundError:
    print("no such file")
no such file
  • Name the exception you expect. A bare except: also hides typing mistakes in your own code, such as a misspelt name.
  • Keep the try block small: only the lines that can raise the error you handle.

Raising errors

A function that is given bad input should say so, not return a wrong answer. raise stops the function with an exception, and the message tells the caller what was wrong.

def parse_trip(row):
    parts = row.split(",")
    if len(parts) != 3:
        raise ValueError(f"expected 3 fields, got {len(parts)}: {row!r}")
    walker, trail, km = parts
    return walker, trail, int(km)

print(parse_trip("ana,Loop,12"))
('ana', 'Loop', 12)
parse_trip("ana,Loop")
ValueError: expected 3 fields, got 2: 'ana,Loop'

The caller decides what a bad row means. Here bad rows are set aside and the rest are kept; int("x") raises ValueError as well, so one handler covers both kinds of bad row.

good = []
bad = []
for row in ["ana,Loop,12", "ana,Loop", "ben,Falls,x"]:
    try:
        good.append(parse_trip(row))
    except ValueError:
        bad.append(row)
print(good)
print(bad)
[('ana', 'Loop', 12)]
['ana,Loop', 'ben,Falls,x']

Writing a file

write takes one string and adds no line break of its own, so each line ends with "\n". Numbers are converted to text, here by an f-string. Sorting the keys makes the file the same on every run.

totals = {"ben": 7, "ana": 17}
with open("totals.csv", "w", encoding="utf-8") as f:
    f.write("walker,km\n")
    for walker in sorted(totals):
        f.write(f"{walker},{totals[walker]}\n")

with open("totals.csv", encoding="utf-8") as f:
    print(f.read(), end="")
walker,km
ana,17
ben,7

Mode "w" replaces the file's content; mode "a" adds to its end.

A small program in three functions

The three weeks together: read records from a file, group them in a dictionary, and report them in a fixed order. Each step is one function that takes its input as a parameter and returns its result, so each can be checked on its own.

def read_trips(path):
    trips = []
    with open(path, encoding="utf-8") as f:
        next(f, None)
        for line in f:
            if line.strip():
                trips.append(parse_trip(line.strip()))
    return trips


def km_per_walker(trips):
    totals = {}
    for walker, _trail, km in trips:
        totals[walker] = totals.get(walker, 0) + km
    return totals


def report(totals):
    ranked = sorted(totals.items(), key=lambda pair: (-pair[1], pair[0]))
    return [f"{walker}: {km} km" for walker, km in ranked]


for line in report(km_per_walker(read_trips("trips.csv"))):
    print(line)
ana: 17 km
ben: 7 km
  • next(f, None) reads the header line and throws it away; the None keeps an empty file from raising an error.
  • Only read_trips touches a file. The other two work on plain lists and dictionaries, so they can be tried with a few values typed by hand.
  • report returns lines instead of printing them: the caller may print them, write them to a file or compare them.

Checking your functions

assert states what must be true and raises AssertionError when it is not. A few asserts on small inputs find most mistakes. Choose the cases a function is most likely to get wrong: no input at all, a key seen twice, a tie.

assert km_per_walker([]) == {}
assert km_per_walker([("ana", "Loop", 12), ("ana", "Ridge", 5)]) == {"ana": 17}
assert report({"cy": 5, "ana": 5}) == ["ana: 5 km", "cy: 5 km"]
print("all checks passed")
all checks passed

A failing check stops the program at that line:

assert report({}) == ["nobody"]
AssertionError

Common mistakes

Forgetting to convert. Fields read from a file are strings. Strings are joined by + and compared character by character, so "9" comes after "12".

print("12" + "5", int("12") + int("5"))
print("9" < "12", 9 < 12)
125 17
False True

Reading a file twice. A file is read from front to back once. After the first pass nothing is left; keep the lines in a list if they are needed again.

with open("trips.csv", encoding="utf-8") as f:
    first = f.readlines()
    second = f.readlines()
print(len(first), len(second))
4 0

Printing instead of returning. A function whose result is needed later must return it; see week 2, "Functions".
