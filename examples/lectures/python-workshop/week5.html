Python workshop, week 5: classes and modules

A class

In these notes, the block right after a piece of code shows what that code prints, or the last line of the error it raises.

A class describes a kind of object: the data each object holds and what can be done with it. __init__ runs when an object is created and stores the arguments as attributes of self, the object being made.

class Trail:
    def __init__(self, name, km, climb):
        self.name = name
        self.km = km
        self.climb = climb


loop = Trail("Loop", 12.5, 640)
falls = Trail("Falls", 7.0, 300)
print(loop.name, falls.km)
loop.climb += 60
print(loop.climb, falls.climb)
Loop 7.0
700 300
  • Trail("Loop", 12.5, 640) creates an object and calls __init__ with it as self.
  • Each object has its own attributes: changing loop.climb leaves falls.climb alone.
  • Compared with a dictionary, a misspelt attribute is an error where it is read, and the class says in one place what a trail has.

Methods

A method is a function defined in the class. Its first parameter is self; the call ridge.steepness() passes ridge as self. A method may compute something from the attributes, or change them.

class Trail:
    def __init__(self, name, km, climb):
        self.name = name
        self.km = km
        self.climb = climb

    def steepness(self):
        return self.climb / (self.km * 1000)

    def is_hard(self, limit=800):
        return self.climb >= limit

    def extend(self, km):
        self.km += km


ridge = Trail("Ridge", 5.5, 880)
print(round(ridge.steepness(), 2), ridge.is_hard(), ridge.is_hard(limit=900))
ridge.extend(1.5)
print(ridge.km)
0.16 True False
7.0
  • Inside a method, the object's data is always reached through self.
  • steepness and is_hard return an answer and change nothing; extend changes the object and returns nothing. Keep the two kinds apart.

Printing and comparing objects

Two objects made with the same values are still two objects, and == between them is false unless the class says what equal means:

a = Trail("Loop", 12.5, 640)
b = Trail("Loop", 12.5, 640)
print(a == b, a == a)
False True

__eq__ defines ==, and __repr__ gives the text shown when the object is printed or sits in a printed list.

class Trail:
    def __init__(self, name, km, climb):
        self.name = name
        self.km = km
        self.climb = climb

    def __repr__(self):
        return f"Trail({self.name!r}, {self.km}, {self.climb})"

    def __eq__(self, other):
        return (self.name, self.km, self.climb) == (other.name, other.km, other.climb)


a = Trail("Loop", 12.5, 640)
b = Trail("Loop", 12.5, 640)
print(a)
print(a == b, [a, b])
Trail('Loop', 12.5, 640)
True [Trail('Loop', 12.5, 640), Trail('Loop', 12.5, 640)]

Comparing tuples of the attributes compares them all at once. !r in an f-string shows a string with its quotes.

Objects in collections

Objects go into lists and dictionaries like any value, and everything from the earlier weeks applies, with an attribute where a key or a position was.

trails = [Trail("Loop", 12.5, 640), Trail("Falls", 7.0, 300), Trail("Ridge", 5.5, 880)]
by_climb = sorted(trails, key=lambda trail: trail.climb, reverse=True)
print([trail.name for trail in by_climb])
by_name = {trail.name: trail for trail in trails}
print(by_name["Falls"].km)
print(sum(trail.km for trail in trails))
['Ridge', 'Loop', 'Falls']
7.0
25.0

A list or dictionary holds references to the objects, not copies: changing an object through one of them is seen through the other.

by_name["Falls"].km = 8.0
print(trails[1].km)
8.0

Data classes

A class that mostly holds data can be written as a data class: list the fields with their types, and __init__, __repr__ and __eq__ are written for you.

from dataclasses import dataclass, field


@dataclass
class Trip:
    walker: str
    trail: str
    km: float
    notes: list = field(default_factory=list)


first = Trip("ana", "Loop", 12.5)
second = Trip("ana", "Loop", 12.5)
print(first)
print(first == second)
first.notes.append("muddy")
print(first.notes, second.notes)
Trip(walker='ana', trail='Loop', km=12.5, notes=[])
True
['muddy'] []
  • The types document the fields; Python does not check them when the program runs.
  • A field with a default may be left out when the object is created.
  • A default that is a list must be given as field(default_factory=list), which makes a new list for each object: the same reason as for a function's default in week 2.

A class that owns a collection

A class is most useful when it keeps a collection consistent: every change goes through a method that checks it, and the questions asked of the data are methods too.

class TripLog:
    def __init__(self):
        self.trips = []

    def add(self, walker, trail, km):
        if km <= 0:
            raise ValueError(f"km must be positive, got {km}")
        self.trips.append(Trip(walker, trail, km))

    def total_for(self, walker):
        return sum(trip.km for trip in self.trips if trip.walker == walker)

    def ranking(self):
        totals = {}
        for trip in self.trips:
            totals[trip.walker] = totals.get(trip.walker, 0) + trip.km
        return sorted(totals.items(), key=lambda pair: (-pair[1], pair[0]))


log = TripLog()
log.add("ana", "Loop", 12)
log.add("ben", "Falls", 7)
log.add("ana", "Ridge", 5)
print(log.total_for("ana"), log.total_for("dee"))
print(log.ranking())
17 0
[('ana', 17), ('ben', 7)]
log.add("cy", "Loop", 0)
ValueError: km must be positive, got 0

The refused trip was not stored: the check comes before the append. A walker with no trips has a total of 0, not an error.

Modules

A module is a file of Python code, and import makes its names available. The standard library comes with Python; math and collections are two of its modules.

import math
from collections import Counter, defaultdict

print(math.sqrt(16), math.ceil(7.2), math.floor(7.8))
print(Counter(["ana", "ben", "ana"]).most_common(1))
groups = defaultdict(list)
for walker, km in [("ana", 12), ("ben", 7), ("ana", 5)]:
    groups[walker].append(km)
print(dict(groups))
4.0 8 7
[('ana', 2)]
{'ana': [12, 5], 'ben': [7]}
  • import math gives the module, used as math.sqrt; from collections import Counter gives the name itself.
  • Counter is the counting pattern of week 2 ready made; defaultdict(list) is the grouping pattern: a missing key starts as an empty list.

Your own file is a module too. Code at its top level runs when the file is imported, so keep there only definitions, and start the program under this test, which is true only when the file is run directly:

def main():
    log = TripLog()
    log.add("ana", "Loop", 12)
    print(log.ranking())


if __name__ == "__main__":
    main()

Common mistakes

**Forgetting self.** A name assigned without it is a local variable of the method and is gone when the method returns:

class Tally:
    def __init__(self):
        count = 0


Tally().count
AttributeError: 'Tally' object has no attribute 'count'

A list defined in the class body. It belongs to the class and is shared by every object. Create it in __init__ instead:

class Walker:
    trips = []

    def __init__(self, name):
        self.name = name


ana = Walker("ana")
ben = Walker("ben")
ana.trips.append("Loop")
print(ben.trips)
['Loop']

A method without its parentheses. log.ranking is the method itself; only log.ranking() calls it:

print(callable(log.ranking), type(log.ranking()).__name__)
True list

**Comparing objects of a class without __eq__.** As shown above, == is then true only for the very same object; a test that compares a result with an expected object needs __eq__, or a data class.
