Python and course packages

  1. Install a Python matching the declared version from Python downloads or your distribution's package manager. Do not assume the newest Python works with the course's libraries.
  2. Return to Install on this machine and use Install into .venv. This installs the tutor and declared pip packages into the course folder, not Java, Hadoop or a compiler.
  3. Use the environment check there. When a different installed Python can fix a compatibility issue, the existing check offers a Python switch; review it before rebuilding the venv.
  4. Open the course in VS Code and use its activated .venv terminal for tests. The command-line check is python -m tutor.envcheck, with WORKSPACE_DIR set to the course folder.

Python installer locations, administrator rights and PATH changes depend on the installer; review its options. Undo through that installer's uninstall instructions. The GUI only manages the course venv.

Java (JDK)

Required version prefix: {{ requires.java }}.

{% if requires.java == '17' %} {% if platform == 'macos' %}

With Homebrew already installed, in your terminal:

brew install openjdk@17
brew --prefix openjdk@17

This downloads the JDK and dependencies into Homebrew's prefix, without sudo. Set JAVA_HOME to that prefix plus /libexec/openjdk.jdk/Contents/Home. Undo the JDK with brew uninstall openjdk@17 and remove your own JAVA_HOME setting.

Source: Homebrew OpenJDK 17.

{% elif platform == 'windows' %}

In PowerShell, with winget available:

winget install Microsoft.OpenJDK.17

Review the installer location, PATH options and any administrator prompt. Set JAVA_HOME to the installed JDK folder. Undo through Windows Installed apps and remove your own JAVA_HOME setting.

Hadoop

Required version prefix: {{ requires.hadoop }}.

{% if platform == 'windows' %}

MRJob's Hadoop runner is unsupported on native Windows: those tests are skipped, and validation does not accept that result. Use the WSL instructions or the course container. Install WSL.

{% elif requires.hadoop in ('3', '3.3', '3.3.6') %}
  1. Download the matching binary archive from Apache's Hadoop 3.3.6 archive and verify its checksum/signature using the files there.
  2. Unpack it into a user-owned folder. Set HADOOP_HOME to that folder and JAVA_HOME to the compatible JDK. No administrator rights or HDFS/YARN services are needed for standalone mode.
  3. In that terminal run "$HADOOP_HOME/bin/hadoop" version, then return to the environment check.

This installs files only where you unpack them; setting PATH or a shell profile is your choice. Undo by removing the unpacked folder and your environment settings.

{% else %}

Spark on native Windows

Spark file access also needs matching winutils.exe and hadoop.dll in HADOOP_HOME\bin, with that folder on PATH. Restart the terminal and VS Code after changing PATH; a local .env value alone does not make Windows find the DLL.

The existing check reports missing winutils files. Third-party binaries require a separate trust decision; this page does not download them. A course container or WSL avoids this native Windows setup. See Spark 3.5 documentation for that series; other versions need their matching documentation. This does not enable MRJob's Hadoop runner on Windows.
